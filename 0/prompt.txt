Проверь: ssh -o ControlPath=/tmp/ssh-alba-%r@%h:%p alba "docker ps --format '{{.Names}}\t{{.Status}}' | grep xoegttvi" (жди свежий суффикс контейнера), затем проверь что новые env применились: docker exec <новое_имя_контейнера> env | grep PARSER_WORKER. Затем проверь end-to-end: curl -s -X POST https://hub.alba-creation.ru/api/parser-niches -H 'Content-Type: application/json' -d '{"category":"тест-е2е","description":"проверка связи с воркером"}' — сохрани id из ответа, затем curl -s -X POST https://hub.alba-creation.ru/api/parser-niches/<id>/run — если это вернёт статус queued/running (не ошибку связи с воркером), значит Node-бэкенд успешно достучался до parser-worker через docker bridge (10.0.1.1:8787). Подожди 10 сек, проверь GET .../status чтобы увидеть лог. Затем удали тестовую нишу: curl -X DELETE https://hub.alba-creation.ru/api/parser-niches/<id>. Если сеть между контейнером и воркером не работает (ошибка connect/timeout в ответе /run) — задиагностируй (проверь ufw, docker network, попробуй curl из контейнера hub на 10.0.1.1:8787/health через docker exec) и почини. Работай автономно без вопросов (пользователь разрешил). После проверки следующим шагом обнови ansible-плейбук проекта (infra/ansible/) чтобы отразить новую инфраструктуру parser-worker (systemd unit-файлы, установка Xvfb/x11vnc/novnc/python3-venv, ufw-правило, nginx location /vnc/) для консистентности с остальным проектом, закоммить и запушь.
