АРХИТЕКТУРА
КАК РАБОТАЮТ АГЕНТЫ (ТЕХНИЧЕСКИ)
Researcher — от RSS до брифа в Telegram

Раз в день (8:30, system cron на VPS, дожил ещё с эпохи Vercel Cron — сейчас просто curl POST на /api/agent-researcher/run) агент читает список RSS-источников из agent_settings, чистит HTML из каждой статьи, считает embedding для каждого кандидата и для описания каждого продукта (project_info: about + ЦА + посыл + отличия + возражения + ключевые слова — конкатенация всех полей, не только about). Дальше — не LLM, а обычная косинусная близость между векторами: у какого продукта вектор ближе, тот и «выиграл» этот кандидат. Топ-3 по релевантности сохраняются как «тренды» в agent_runs.brief_json, отдаются наружу через /latest-brief и коротко пересказываются в Telegram.

Generator — облачная рутина, а не сервер

Это не код в этом репозитории, а Claude Code routine в облаке Anthropic (создана через RemoteTrigger, cron 9:15 Amsterdam). Работает в собственном изолированном окружении с Custom network access — по умолчанию облачная песочница блокирует произвольные исходящие домены, поэтому hub.alba-creation.ru явно добавлен в allowlist. Каждый запуск: GET /latest-brief → GET /agent-settings → пишет пост по формуле «Золотая середина» СТРОГО как 4 отдельных поля (businessProblem/technicalSolution/businessResult/cta), не единым текстом → POST /api/ideas. Сервер сам собирает финальный текст и прогоняет его через Editor (validateDraft — обычный код, без AI): проверка длины полей, наличие измеримой метрики в результате (регулярка на %, «в N раз», сумму), лимит символов под формат. Готовый черновик уходит в Telegram на approve/reject/regenerate.

КЛЮЧЕВЫЕ РЕШЕНИЯ
Почему parser-worker не в обычном Docker-приложении Coolify

2ГИС блокирует headless-браузеры. Xvfb внутри контейнера создаёт виртуальный дисплей, Chromium запускается в обычном (не headless) режиме и выглядит как настоящий браузер — тот же трюк, что у официальных Selenium-образов.

Почему Coolify-контейнеры видны друг другу только по портам, не по имени

Имя контейнера у Coolify меняется на каждом деплое. Поэтому hub достаётся до parser-worker, LibreTranslate, Piper и video-worker через docker bridge gateway (10.0.1.1) + опубликованный на хосте порт — этот адрес стабилен независимо от редеплоя. Каждый порт дополнительно закрыт правилом ufw только для подсети Coolify.

Почему перевод и генерация запросов парсера — не через Claude API

Это либо детерминированная задача (разбивка текста на ключевые слова), либо задача, для которой есть бесплатный специализированный инструмент (LibreTranslate) — платный LLM-вызов был бы избыточен для обеих.

Почему Editor проверяет черновики без AI

Generator обязан отдавать структуру поста как отдельные поля (проблема/решение/результат), а не единым текстом — тогда проверка «всё на месте» становится обычным кодом, не задачей на понимание смысла.

Почему Piper — рядом с ElevenLabs, а не вместо

Piper бесплатный и офлайн, но с одним голосом среднего качества. ElevenLabs — платный, но заметно лучше по качеству и выбору голосов. Оба провайдера выбираются в форме генерации озвучки, ни один не убирает другой.

Почему X (Twitter) нет в списке площадок публикации

У X с недавнего времени платный API для постинга. Threads (отдельное приложение Meta) закрывает тот же формат «тред» бесплатно (с App Review), поэтому в качестве формата контента остался только «Threads», без привязки к X.

Каналы для публикации

Один бот (токен выше) может публиковать в несколько каналов, где он админ. Эти каналы появятся в выборе при публикации идеи из «Банка идей».

Токен сообщества (community access token) с правом wall — создаётся в настройках сообщества VK или через Standalone-приложение.

Page access token из приложения Meta Graph API, привязанного к странице Facebook с подключённым Instagram Business/Creator аккаунтом.

OAuth2-приложение из Google Cloud Console + refresh token, полученный один раз через экран согласия (не просто токен, как в Telegram/VK).

Threads user access token из приложения Meta с use case "Threads" (не Facebook Graph API) — нужны разрешения threads_basic и threads_content_publish, аккаунт должен пройти App Review.
