ДАННЫЕ И ХРАНИЛИЩЕ
Turso (libSQL)● работает

Облачная БД со всеми бизнес-данными — продукты, идеи, медиа, настройки агентов. Отдельный сервис, не в Coolify.

S3-хранилище (SeaweedFS)● работает

Self-hosted S3-совместимое хранилище на Coolify. Постоянные ссылки на обложки/видео/озвучку вместо base64 и временных URL от kie.ai. Публично раздаётся через nginx /media/.

SELF-HOSTED СЕРВИСЫ (COOLIFY)
parser-worker● работает

Xvfb + headed Chromium + Playwright — обходит блокировку headless-браузеров у 2ГИС (внешний сервис). Очередь job'ов, noVNC для ручного решения капчи, + загрузка готовых Excel-списков.

LibreTranslate● работает

Свои модели en/ru, переводит карточки идей на английский. Бесплатная альтернатива платным translation API.

Piper TTS● работает

Офлайн нейросетевая озвучка (ru_RU-dmitri). Бесплатная альтернатива ElevenLabs — выбирается в форме генерации озвучки.

video-worker● работает

FFmpeg-сборка Shorts: видео-клип + озвучка + субтитры → готовый вертикальный ролик. Порт 8788 опубликован, VIDEO_WORKER_URL настроен — финальная сборка ролика в кнопке «Сгенерировать» доступна.

scrape-worker (ScrapeGraphAI)○ ждёт ключей

Вторая база заказчиков — обходит произвольные сайты компаний Playwright'ом и разбирает контакты моделью на локальной Ollama (не 2ГИС, дополняет его). Отдельный docker compose (см. scrape-worker/README.md): поднять контейнеры, один раз выполнить ollama pull qwen2.5:7b и ollama pull nomic-embed-text (иначе первый job падает с «model not found»), затем в `.env` хаба — SCRAPE_WORKER_URL и тот же SCRAPE_WORKER_TOKEN, что задан воркеру. Проверить связку — «Заказчики» → ScrapeGraph, вверху панели видно, на связи ли воркер.

ГЕНЕРАЦИЯ МЕДИА (ВНЕШНИЕ API)
kie.ai (Flux / Kling)● работает

AI-обложки (Flux) и видео-клипы (Kling) по запросу. KIE_API_KEY настроен.

ElevenLabs○ требует оплаты

Платная озвучка высокого качества, несколько голосов на выбор. Ключ добавлен, но план ElevenLabs не оплачен — запросы будут падать с ошибкой оплаты, пока не куплен тариф.

ПУБЛИКАЦИЯ (ВНЕШНИЕ API)
VK○ ждёт ключей

wall.post, один community-токен на всё (как у Telegram — не два аккаунта). Публикует в любое из добавленных сообществ (vk_groups) — сообщество выбирается в модалке публикации/планирования, с подсказкой по умолчанию исходя из языка поста. Ждёт токена в настройках.

Instagram○ ждёт ключей

Graph API, нужен Business-аккаунт. Два отдельных аккаунта — RU и EN, аккаунт выбирается автоматически по языку публикуемого поста, без ручного пикера. Оба ждут токена в настройках (переключатель RU/EN в форме).

YouTube○ ждёт ключей

Data API v3, resumable upload. Два отдельных OAuth-аккаунта — RU и EN, выбор автоматический по языку поста. register-youtube-oauth.mjs теперь принимает --lang ru|en, нужно прогнать дважды по одному на каждый аккаунт.

Threads○ ждёт ключей

Отдельный API Meta (graph.threads.net), не тот же что у Instagram. Два отдельных аккаунта — RU и EN, выбор автоматический по языку поста. Ждёт App Review от Meta для обоих.

Pinterest○ ждёт ключей

API v5, каждый пин обязательно на доску (board_id) — доска выбирается при публикации или задаётся по умолчанию в настройках. Требует обложку, текст-онли пины не поддерживаются. Один аккаунт на оба языка (как VK) — у Pinterest нет RU/EN-разделения.

Telegram намеренно не тронут — там уже работает своя схема из нескольких каналов под одним ботом (см. ниже «Хранилище постов»).

ЛОКАЛЬНЫЙ АГЕНТ (ВАШ ПК)

Не на VPS — два Docker-контейнера на вашем компьютере (docker-compose, restart:unless-stopped), пробрасываются наружу постоянным доменом ngrok.

local-claude-agent● работает

Обёртка над настоящим `claude` CLI (не root, --allowedTools WebSearch, авторизован вашей подпиской через CLAUDE_CODE_OAUTH_TOKEN). Фиксированный набор задач, не generic-исполнение промптов: поиск RSS-источников и ключевых слов, описание ниши парсера, сценарий для Reels, определение города для 2ГИС-парсера, питч для холодных звонков, генерация раздела скрипта звонка, AI-ревью юридических находок, «с чистого листа» генерация поста (4 формата + перевод), подбор актуальной темы с источниками.

ngrok-туннель● работает

Сайдкар-контейнер, постоянный зарезервированный домен (не меняется при перезапуске). hub стучится в него как в обычный HTTPS-эндпоинт через LOCAL_CLAUDE_AGENT_URL.

АГЕНТЫ (АВТОМАТИЗАЦИЯ)

Стрелка обратная: агенты сами дёргают REST API hub'а по расписанию (cron / routine), а не hub вызывает их.

Researcher● работает

System cron на VPS, каждый день в 8:30. Читает RSS, считает embeddings локально (без LLM) и находит ближайший по смыслу продукт — cosine similarity. → POST /agent-researcher/run.

Generator● работает

Claude Code routine в облаке Anthropic, каждый день в 9:15 (Amsterdam). Читает бриф от Researcher и текущий стратегический контекст (GET /api/content-plan/context — цель, дистрибуция, фокус квартала и дня, подтягивается прямо из «Контент-плана»), пишет пост по формуле «Золотая середина», шлёт черновик в Telegram на approve.

Insights● работает

Claude Code routine в облаке Anthropic, каждый понедельник в 8:20 (Amsterdam летом — UTC-время фиксировано, зимой сдвинется на час). Читает /insights/brief за 7 дней, ищет закономерности по форматам/рубрикам, пишет выводы в agent_runs.

Маркетолог (Marketing)● работает

Claude Code routine в облаке Anthropic, каждый понедельник в 8:37 (сразу после Insights). Читает /api/marketing/brief (трата по агентам, cost-per-post, cost-per-lead) плюс последние выводы Insights и текущий квартал контент-плана, пишет вывод по эффективности расходов в agent_runs. Эти выводы попадают в /api/content-plan/context — тот же контекст, что читают Researcher и Generator, так что вся система реагирует на них, а не только страница Аналитики.

Metrics Sync● работает

System cron на VPS, каждые 6 часов. Подтягивает просмотры/лайки/сохранения с VK/Instagram/YouTube/Pinterest обратно в scheduled_events по опубликованным постам. Telegram — исключение: Bot API физически не отдаёт число просмотров, это ограничение платформы, не баг.

КАК РАБОТАЮТ АГЕНТЫ (ТЕХНИЧЕСКИ)
Researcher — от RSS до брифа в Telegram

Раз в день (8:30, system cron на VPS, дожил ещё с эпохи Vercel Cron — сейчас просто curl POST на /api/agent-researcher/run) агент читает список RSS-источников из agent_settings, чистит HTML из каждой статьи, считает embedding для каждого кандидата и для описания каждого продукта (project_info: about + ЦА + посыл + отличия + возражения + ключевые слова + роадмап продвижения — конкатенация всех полей, не только about). Дальше — не LLM, а обычная косинусная близость между векторами: у какого продукта вектор ближе, тот и «выиграл» этот кандидат. Топ-3 по релевантности сохраняются как «тренды» в agent_runs.brief_json, отдаются наружу через /latest-brief и коротко пересказываются в Telegram.

Generator — облачная рутина, а не сервер

Это не код в этом репозитории, а Claude Code routine в облаке Anthropic (создана через RemoteTrigger, cron 9:15 Amsterdam). Работает в собственном изолированном окружении с Custom network access — по умолчанию облачная песочница блокирует произвольные исходящие домены, поэтому hub.alba-creation.ru явно добавлен в allowlist. Каждый запуск: GET /latest-brief → GET /agent-settings → пишет пост по формуле «Золотая середина» СТРОГО как 4 отдельных поля (businessProblem/technicalSolution/businessResult/cta), не единым текстом → POST /api/ideas. Сервер сам собирает финальный текст и прогоняет его через Editor (validateDraft — обычный код, без AI): проверка длины полей, наличие измеримой метрики в результате (регулярка на %, «в N раз», сумму), лимит символов под формат. Готовый черновик уходит в Telegram на approve/reject/regenerate.

КЛЮЧЕВЫЕ РЕШЕНИЯ
Почему Telegram-запросы идут через Cloudflare Worker, а не напрямую

api.telegram.org недоступен напрямую с VPS (проверено: стабильный таймаут 10 сек, при этом google.com/github.com открываются мгновенно — точечная блокировка именно этого хоста, не общая проблема сети). Все обращения к Telegram в этом приложении идут через telegramApiBase() (server/lib/telegramApiBase.js), которая читает TELEGRAM_API_BASE_URL — бесплатный Cloudflare Worker (cloudflare-worker-telegram-proxy/) просто перебрасывает запрос на настоящий api.telegram.org со своей инфраструктуры.

Почему RSS-поиск и описание ниши работают через ваш ПК, а не через API-ключ на сервере

Разовый запуск `claude` CLI под вашей же подпиской (не отдельный платный Anthropic API-ключ) дешевле и не требует нового биллинга. Из-за этого он физически должен работать там, где есть подписка — на вашем компьютере, а не на VPS — отсюда local-claude-agent + туннель наружу, а не обычный серверный вызов.

Почему parser-worker не в обычном Docker-приложении Coolify

2ГИС блокирует headless-браузеры. Xvfb внутри контейнера создаёт виртуальный дисплей, Chromium запускается в обычном (не headless) режиме и выглядит как настоящий браузер — тот же трюк, что у официальных Selenium-образов.

Почему Coolify-контейнеры видны друг другу только по портам, не по имени

Имя контейнера у Coolify меняется на каждом деплое. Поэтому hub достаётся до parser-worker, LibreTranslate, Piper и video-worker через docker bridge gateway (10.0.1.1) + опубликованный на хосте порт — этот адрес стабилен независимо от редеплоя. Каждый порт дополнительно закрыт правилом ufw только для подсети Coolify.

Почему перевод и генерация запросов парсера — не через Claude API

Это либо детерминированная задача (разбивка текста на ключевые слова), либо задача, для которой есть бесплатный специализированный инструмент (LibreTranslate) — платный LLM-вызов был бы избыточен для обеих.

Почему Editor проверяет черновики без AI

Generator обязан отдавать структуру поста как отдельные поля (проблема/решение/результат), а не единым текстом — тогда проверка «всё на месте» становится обычным кодом, не задачей на понимание смысла.

Почему Piper — рядом с ElevenLabs, а не вместо

Piper бесплатный и офлайн, но с одним голосом среднего качества. ElevenLabs — платный, но заметно лучше по качеству и выбору голосов. Оба провайдера выбираются в форме генерации озвучки, ни один не убирает другой.

Почему X (Twitter) нет в списке площадок публикации

У X с недавнего времени платный API для постинга. Threads (отдельное приложение Meta) закрывает тот же формат «тред» бесплатно (с App Review), поэтому в качестве формата контента остался только «Threads», без привязки к X.

КАК ПОЛЬЗОВАТЬСЯ ХАБОМ

Типовой пользовательский сценарий — от идеи из ленты до опубликованного поста.

1
Утро — проверяете TelegramTelegram-бот

В 8:30 Researcher присылает сводку найденных тем, в 9:15 Generator — уже готовый черновик поста по одному из продуктов. В чате: approve / reject / regenerate.

2
Approved-черновик открываете в «Хранилище постов»Хранилище постов

Читаете/правите текст, при необходимости меняете формат (TG-пост / Reels / Threads / Лонгрид), рубрику и этап воронки (TOFU/MOFU/BOFU). Черновики «с чистого листа» (тема → 4 формата → перевод) пишутся отдельно на «Создании контента» — там же, ещё до утверждения, подбирается и обложка.

3
Обложка — заранее, озвучка — после утвержденияСоздание контента · Хранилище постов

Обложку (AI, kie.ai Flux, можно сгенерировать несколько вариантов и выбрать) подбираете ещё во время написания текста на «Создании контента» — отклонённые варианты не пропадают, а складываются в Медиатеку папкой по теме, для переиспользования потом. Озвучка (ElevenLabs или Piper TTS) генерируется отдельной кнопкой на карточке в «Хранилище», но только после того как идея утверждена (текст уже финальный, менять больше не планируется).

4
Публикуете с карточки идеиХранилище постов

На карточке выбираете площадку (VK / Instagram / YouTube / Threads / Pinterest / нужный Telegram-канал), язык RU или EN, жмёте «Опубликовать» — открывается окно подтверждения с превью, и только после него пост уходит на площадку. Ничего не публикуется по одному клику без этого шага.

5
Планируете дату и двигаете по пайплайнуКалендарь · CRM

В «Календаре» назначаете дату и время публикации — дальше пост уходит на площадку сам, без ручного клика. В CRM на доске «Контент» колонки уже не про стадию редактирования, а про весь путь публикации: 💡 Идея → Готово к публикации → Запланировано → Опубликовано (идёт сбор метрик) → Завершено. Первые две двигаете сами, «Запланировано»/«Опубликовано» проставляются автоматически по календарю, в «Завершено» переносите руками, когда посмотрели разбор (кнопка «🔍 Анализ» появляется на карточке через 14 дней после публикации).

6
Смотрите, что сработалоДашборд & Аналитика · Архив публикаций

Аналитика теперь по возможности сама: автосводка просмотров/сохранений/кликов по площадкам (как только подключены токены VK/Instagram/YouTube — для Telegram это в принципе недоступно через Bot API), стоимость поста и лида из Cost Tracker, и только лиды остаются на ручной ввод — их никакая площадка не отдаёт по API. «Архив публикаций» — список всего, что реально вышло, с датой/площадкой/метриками.

7
Продукт «не туда» матчится — донастраиваете описаниеПродукты

Вспомогательные вкладки — по мере надобностиСкрипты · Заказчики · Проверка сайта · Центр агентов

«Скрипты» — сценарии живых звонков по нишам, там же теперь и предложение для холодных звонков в Telegram (переехало сюда с «Заказчиков» — оно про продажи, не про сбор базы). «Заказчики» — теперь две базы: парсер 2ГИС по нишам (город любой, определяется через ИИ и веб-поиск) плюс ScrapeGraph — вторая база с произвольных сайтов компаний (нужен отдельно поднятый scrape-worker, см. карточку выше в СЕЛФ-ХОСТЕД СЕРВИСАХ), обе сливаются в общую сводную таблицу по телефону/домену/названию. «Проверка сайта» — юридический и нагрузочный аудит, плюс AI-ревью находок через local-claude-agent, снижает число ложных срабатываний. «Центр агентов» — RSS-источники, тон голоса, промпт Generator'а (теперь ссылается на GET /api/content-plan/context — правки в «Контент-плане» долетают до генерации без ручного дублирования текста), рубрики и история/расходы запусков.

В отличие от Telegram-бота, токен доступа VK привязан к своему сообществу — у каждого сообщества свой токен (Управление сообществом → Работа с API → Ключи доступа), не общий. Вставьте токен — сообщество определится по нему автоматически, название можно не указывать.

OAuth2-приложение из Google Cloud Console + refresh token, полученный один раз через экран согласия (не просто токен, как в Telegram/VK). Два отдельных канала/аккаунта — RU и EN, выбирается автоматически по языку публикуемого поста (см. scripts/register-youtube-oauth.mjs --lang).

Threads user access token из приложения Meta с use case "Threads" (не Facebook Graph API) — нужны разрешения threads_basic и threads_content_publish, аккаунт должен пройти App Review. Два отдельных аккаунта — RU и EN, выбирается автоматически по языку публикуемого поста.
