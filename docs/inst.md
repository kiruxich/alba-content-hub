# Instagram + Threads: подключение (на будущее)

Статус на момент написания: заблокировано на регистрации Meta for
Developers (см. «Проблемы с верификацией» ниже) — техническая часть в хабе
полностью готова и ждёт только реальных токенов. Когда верификация
пройдёт, весь этот документ — чек-лист, что делать дальше.

## Что уже готово в хабе (ничего чинить не нужно)

- **Instagram**: два отдельных аккаунта в БД (RU/EN, `instagram_settings`),
  выбираются автоматически по языку публикуемого поста — см.
  `server/lib/socialPublishers/instagram.js`.
- **Threads**: то же самое, два отдельных аккаунта RU/EN
  (`threads_settings`) — см. `server/lib/socialPublishers/threads.js`.
- **Instagram-панель конкурентов** («Центр агентов» → «Instagram —
  отслеживание аккаунтов»): ручной список чужих юзернеймов + кнопка
  «Обновить», читает последние посты через Business Discovery API. Не
  требует отдельной настройки — заработает сама, как только появится хотя
  бы один настроенный Instagram-аккаунт (RU или EN, не важно какой —
  используется только для чтения).
- Настройки публикации (токены) вводятся в хабе: **Публикации →
  Instagram / Threads** — там уже есть переключатель RU/EN для каждой
  платформы.

## Шаг 1 — создать приложение в Meta for Developers

1. `developers.facebook.com` → войти **существующим личным Facebook-
   аккаунтом** (не через отдельную регистрацию «Meta for Developers» — тот
   мастер регистрации ненадёжен, см. ниже).
2. «Мои приложения» → **Create App** → тип **Business**.
3. В приложении добавить два продукта: **Instagram** (Graph API) и
   **Threads** (Threads API).

### Проблемы с верификацией (реально встреченные при первой попытке)

- **`Ошибка 403: org_internal`** при попытке войти на экран согласия —
  значит OAuth consent screen приложения настроен как **Internal**
  (доступен только сотрудникам Google Workspace-организации). Фикс:
  `Google Auth Platform → Audience → User Type → сменить на External`,
  оставить **Testing** (не «In production» — ревью Google для публикации
  на свой же канал не нужно), добавить нужные Gmail-адреса в **Test
  users**. (Это про Google/YouTube-эквивалент проблемы — тот же принцип
  верификации применим и к Meta-стороне ниже.)
- **SMS-верификация телефона не проходит** при регистрации нового
  отдельного аккаунта Meta for Developers — известная массовая проблема
  именно с российскими номерами (SMS от Meta к российским операторам с
  2022 года доставляются нестабильно). Это не баг конкретной попытки —
  подтверждено на нескольких аккаунтах/номерах подряд.
  **Обходные пути:**
  1. Войти **существующим личным Facebook-аккаунтом** через кнопку
     «Login»/«Начать» вместо прохождения отдельной регистрации — во
     многих случаях Facebook-аккаунт уже верифицирован, и отдельная
     SMS-верификация для разработчика не запросится повторно.
  2. Если запрос телефона всё равно появляется — временный eSIM с
     иностранным номером (Airalo, Holafly и т.п.), нужен только для
     одной SMS, дальше номер для работы аккаунта не требуется.
  3. Попросить человека с уже верифицированным Meta-аккаунтом создать
     приложение и добавить вас в **Roles → Add People** как
     разработчика/админа — тогда собственная верификация не нужна вообще,
     только принять приглашение под своим Facebook-логином.
  4. Отключить VPN полностью перед попыткой — гео-мисматч (например,
     шведский номер вместо реального) провоцирует блокировки.

## Шаг 2 — подключить Instagram Business/Creator аккаунт

1. Обычный личный Instagram-аккаунт нужно переключить в **Business** или
   **Creator** (Настройки → Аккаунт → Переключиться на профессиональный).
2. Привязать его к Facebook-странице (Instagram Настройки → Подключённые
   аккаунты → Facebook).
3. Повторить для второго (EN) аккаунта — своя Facebook-страница на
   каждый Instagram-аккаунт.

## Шаг 3 — получить токен через Graph API Explorer

1. `developers.facebook.com/tools/explorer` → выбрать созданное
   приложение.
2. Выбрать нужную Facebook-страницу (привязанную к RU-аккаунту) → права
   доступа: `instagram_basic`, `instagram_content_publish`,
   `pages_show_list`, `pages_read_engagement` (для Business Discovery —
   доступа к чужим публичным аккаунтам в панели конкурентов — права
   `instagram_manage_insights` тоже пригодятся).
3. Сгенерировать токен, **обменять на долгоживущий** (Access Token
   Debugger → Extend Access Token) — короткоживущий токен истечёт через
   час, это нужно сделать один раз.
4. Business Account ID достать отдельным запросом:
   `GET /me/accounts` → в ответе `instagram_business_account.id`.
5. Повторить весь шаг для EN-аккаунта отдельно.

## Шаг 4 — вставить в хаб

Настройки публикации → вкладка Instagram → переключатель RU/EN → вставить
токен + Business Account ID для каждого языка → Сохранить.

## Шаг 5 — Threads (после Instagram)

1. В том же Meta-приложении — продукт **Threads API** уже добавлен на
   шаге 1.
2. Подать **App Review** — без него публикация не пройдёт даже с
   валидным токеном, доступно только тестовым аккаунтам, добавленным в
   приложение. Ревью может занять от нескольких дней до пары недель.
3. После одобрения — получить токен с правами `threads_basic`,
   `threads_content_publish` тем же способом (Graph API Explorer, но
   для Threads используется `graph.threads.net`, не тот же endpoint что
   у Instagram).
4. Threads user ID — аналогично Instagram, через `/me` запрос с
   Threads-токеном.
5. Вставить в хаб: Настройки публикации → Threads → RU/EN → Сохранить.

## Проверка после настройки

- Настройки публикации → открыть вкладку Instagram/Threads → должно
  показывать `hasToken: true` и превью последних символов токена, а не
  «не настроен».
- Центр агентов → «Instagram — отслеживание аккаунтов» → добавить любой
  публичный юзернейм → «Обновить» → должны появиться реальные посты (это
  же подтверждает, что Business Discovery работает, не только публикация).
- Пробная публикация — сначала на тестовую идею, не на реальный контент,
  чтобы убедиться, что оба языковых аккаунта публикуют туда, куда нужно.
